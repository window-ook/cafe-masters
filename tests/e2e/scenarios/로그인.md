# 로그인 기능 테스트 시나리오

## 개요
사용자 로그인 기능의 모든 플로우를 검증하는 시나리오입니다.

## 우선순위
**Critical (P0)** - 모든 주요 기능 이용을 위한 필수 전제조건

## 시나리오 1: 정상 이메일 로그인

### 목적
유효한 이메일과 비밀번호로 정상 로그인이 가능한지 검증

### 전제조건
- 가입된 테스트 계정 존재
- 메인 페이지 접속 상태

### 테스트 단계
1. 사이드바에서 "로그인" 버튼 클릭
2. `/signin` 페이지 이동 확인
3. 이메일 입력 필드에 유효한 이메일 입력
4. 비밀번호 입력 필드에 올바른 비밀번호 입력
5. "접속하기" 버튼 클릭
6. 로그인 성공 후 메인 페이지 리다이렉트 확인
7. 사이드바에서 로그인 상태 변경 확인

### 예상 결과
- 로그인 페이지가 정상 로드됨
- 폼 입력이 정상적으로 처리됨
- 로그인 성공 후 `/main` 페이지로 이동
- 사이드바에 사용자 정보 또는 로그아웃 버튼 표시

### 실패 조건
- 로그인 페이지 접근 불가
- 폼 입력 처리 실패
- 로그인 처리 실패
- 페이지 리다이렉트 실패

## 시나리오 2: 잘못된 로그인 정보 처리

### 목적
잘못된 로그인 정보 입력 시 적절한 에러 메시지가 표시되는지 검증

### 전제조건
- 로그인 페이지 접속 상태

### 테스트 단계
1. **잘못된 이메일 테스트**
   - 존재하지 않는 이메일 입력
   - 유효한 비밀번호 입력
   - "접속하기" 버튼 클릭
   - 에러 메시지 확인

2. **잘못된 비밀번호 테스트**
   - 유효한 이메일 입력
   - 잘못된 비밀번호 입력
   - "접속하기" 버튼 클릭
   - 에러 메시지 확인

3. **빈 필드 테스트**
   - 이메일 또는 비밀번호 빈 상태로 제출
   - 유효성 검사 메시지 확인

### 예상 결과
- 각 상황에 맞는 구체적인 에러 메시지 표시
- 폼이 초기화되지 않고 입력값 유지
- 페이지 리로드 없이 에러 처리
- 에러 후에도 재입력 가능

### 실패 조건
- 에러 메시지 누락 또는 부정확
- 페이지 크래시 또는 무한 로딩
- 폼 입력값 유실
- 보안 취약점 노출

## 시나리오 3: 카카오 OAuth 로그인

### 목적
카카오 소셜 로그인 버튼 클릭 시 올바른 리다이렉트가 발생하는지 검증

### 전제조건
- 로그인 페이지 접속 상태
- 카카오 OAuth 설정 완료

### 테스트 단계
1. "카카오 로그인" 버튼 존재 확인
2. "카카오 로그인" 버튼 클릭
3. 카카오 인증 페이지로 리다이렉트 확인
4. 카카오 도메인 URL 확인

### 예상 결과
- 카카오 로그인 버튼이 정상 표시됨
- 버튼 클릭 시 카카오 인증 페이지로 이동
- 올바른 카카오 OAuth URL로 리다이렉트
- 인증 흐름이 시작됨

### 실패 조건
- 카카오 로그인 버튼 누락
- 리다이렉트 실패
- 잘못된 OAuth URL
- 인증 과정 에러

## 시나리오 4: 네비게이션 및 폼 전환

### 목적
로그인 페이지에서 다른 인증 관련 페이지로의 이동이 정상 동작하는지 검증

### 전제조건
- 로그인 페이지 접속 상태

### 테스트 단계
1. **회원가입 페이지 이동**
   - "계정이 없으신가요? 회원가입" 링크 클릭
   - `/signup` 페이지 이동 확인
   - 회원가입 폼 표시 확인

2. **비밀번호 재설정 페이지 이동**
   - 로그인 페이지로 되돌아가기
   - "비밀번호 재설정" 링크 클릭
   - `/reset-password` 페이지 이동 확인

3. **폼 간 데이터 일관성**
   - 각 페이지에서 동일한 UI/UX 패턴 확인
   - 브랜딩 및 스타일 일관성 확인

### 예상 결과
- 모든 네비게이션 링크가 정상 동작
- 각 페이지가 올바른 경로로 이동
- 일관된 디자인 시스템 적용
- 사용자 경험 연속성 유지

### 실패 조건
- 네비게이션 링크 동작 실패
- 잘못된 페이지 이동
- 디자인 불일치
- 사용자 경험 단절

## 시나리오 5: 브라우저 백/포워드 및 직접 URL 접근

### 목적
브라우저 네비게이션 및 직접 URL 접근 시 로그인 상태가 올바르게 처리되는지 검증

### 전제조건
- 로그인된 사용자 상태

### 테스트 단계
1. **로그인 후 브라우저 백 버튼 테스트**
   - 로그인 완료 상태
   - 브라우저 뒤로가기 버튼 클릭
   - 로그인 페이지 접근 차단 확인

2. **직접 URL 접근 테스트**
   - 로그인된 상태에서 `/signin` 직접 접근
   - 메인 페이지로 리다이렉트 확인

3. **로그아웃 후 보호된 페이지 접근**
   - 로그아웃 수행
   - 보호된 페이지(컬렉션, 북마크) 접근 시도
   - 로그인 페이지로 리다이렉트 확인

### 예상 결과
- 로그인된 사용자는 로그인 페이지 접근 차단
- 적절한 리다이렉트 처리
- 보호된 리소스에 대한 접근 제어
- 세션 상태 정확한 관리

### 실패 조건
- 중복 로그인 페이지 접근 허용
- 리다이렉트 루프 발생
- 인증 상태 불일치
- 보안 취약점 발생
