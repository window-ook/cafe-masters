# 회원가입 기능 테스트 시나리오

## 개요
신규 사용자 회원가입 프로세스의 모든 플로우를 검증하는 시나리오입니다.

## 우선순위
**High (P1)** - 신규 사용자 유입을 위한 핵심 기능

## 시나리오 1: 정상 이메일 회원가입

### 목적
유효한 정보로 정상적인 회원가입이 가능한지 검증

### 전제조건
- 회원가입 페이지 접속 가능
- 사용되지 않은 이메일 주소 준비

### 테스트 단계
1. 로그인 페이지에서 "회원가입" 링크 클릭
2. `/signup` 페이지 이동 확인
3. 이메일 입력 필드에 신규 이메일 입력
4. 비밀번호 입력 필드에 유효한 비밀번호 입력 (영문+숫자, 6자 이상)
5. "가입하기" 버튼 클릭
6. 회원가입 성공 처리 확인
7. 자동 로그인 또는 로그인 페이지 이동 확인

### 예상 결과
- 회원가입 페이지가 정상 로드됨
- 폼 입력이 정상적으로 처리됨
- 회원가입 성공 메시지 또는 리다이렉트
- 신규 계정으로 로그인 가능

### 실패 조건
- 페이지 로딩 실패
- 폼 제출 처리 실패
- 데이터베이스 저장 실패
- 후속 프로세스 진행 불가

## 시나리오 2: 비밀번호 유효성 검증

### 목적
비밀번호 입력 규칙이 올바르게 검증되는지 확인

### 전제조건
- 회원가입 페이지 접속 상태

### 테스트 단계
1. **너무 짧은 비밀번호 테스트**
   - 유효한 이메일 입력
   - 5자 이하 비밀번호 입력
   - "가입하기" 버튼 클릭
   - 에러 메시지 확인

2. **영문만 포함된 비밀번호 테스트**
   - 영문자만 6자 이상 입력
   - 에러 메시지 확인

3. **숫자만 포함된 비밀번호 테스트**
   - 숫자만 6자 이상 입력
   - 에러 메시지 확인

4. **유효한 비밀번호 테스트**
   - 영문+숫자 조합 6자 이상 입력
   - 정상 처리 확인

### 예상 결과
- 각 조건별로 정확한 에러 메시지 표시
- "*비밀번호는 최소 6자 이상, 영문과 숫자를 포함해야 합니다." 가이드 표시
- 실시간 또는 제출 시 유효성 검사
- 유효한 비밀번호는 정상 처리

### 실패 조건
- 유효성 검사 누락
- 부정확한 에러 메시지
- 잘못된 비밀번호 허용
- 가이드 메시지 누락

## 시나리오 3: 이메일 중복 검증

### 목적
이미 가입된 이메일로 재가입 시도 시 적절한 처리가 되는지 검증

### 전제조건
- 기존에 가입된 테스트 계정 존재
- 회원가입 페이지 접속 상태

### 테스트 단계
1. 이미 가입된 이메일 주소 입력
2. 유효한 비밀번호 입력
3. "가입하기" 버튼 클릭
4. 중복 이메일 에러 메시지 확인
5. 로그인 페이지로 이동 링크 확인

### 예상 결과
- "이미 가입된 이메일입니다" 형태의 명확한 에러 메시지
- 로그인 페이지로 이동할 수 있는 링크 제공
- 폼 입력값 유지 (이메일 필드)
- 비밀번호 필드는 보안상 초기화

### 실패 조건
- 중복 계정 생성 허용
- 모호한 에러 메시지
- 사용자 가이드 부족
- 보안 정보 노출

## 시나리오 4: 카카오 소셜 회원가입

### 목적
카카오 OAuth를 통한 소셜 회원가입 플로우가 정상 동작하는지 검증

### 전제조건
- 회원가입 페이지 접속 상태
- 카카오 OAuth 설정 완료

### 테스트 단계
1. "카카오 로그인" 버튼 존재 확인
2. "카카오 로그인" 버튼 클릭
3. 카카오 인증 페이지로 리다이렉트 확인
4. 카카오 도메인 및 OAuth 파라미터 확인

### 예상 결과
- 카카오 로그인 버튼이 명확하게 표시됨
- 클릭 시 카카오 인증 페이지로 이동
- 올바른 OAuth 플로우 시작
- 적절한 권한 요청 스코프 설정

### 실패 조건
- 소셜 로그인 버튼 누락
- 잘못된 OAuth 설정
- 리다이렉트 URL 오류
- 권한 스코프 부적절

## 시나리오 5: 폼 네비게이션 및 사용자 경험

### 목적
회원가입 페이지에서의 사용자 경험과 네비게이션이 직관적인지 검증

### 전제조건
- 회원가입 페이지 접속 상태

### 테스트 단계
1. **로그인 페이지 이동**
   - "이미 계정이 있으신가요? 로그인 하기" 링크 클릭
   - `/signin` 페이지 이동 확인

2. **폼 상호작용**
   - 탭(Tab) 키로 필드 간 이동 확인
   - 엔터(Enter) 키로 폼 제출 확인
   - 포커스 인디케이터 표시 확인

3. **반응형 디자인**
   - 모바일 화면에서 폼 레이아웃 확인
   - 터치 친화적 입력 영역 확인
   - 키보드 표시 시 화면 조정 확인

### 예상 결과
- 모든 네비게이션 링크가 정상 동작
- 키보드 접근성 완전 지원
- 모든 화면 크기에서 사용 가능
- 직관적인 사용자 인터페이스

### 실패 조건
- 네비게이션 링크 실패
- 키보드 접근성 부족
- 모바일 사용성 문제
- 혼란스러운 UI/UX

## 시나리오 6: 에러 복구 및 재시도

### 목적
네트워크 오류나 서버 에러 발생 시 적절한 사용자 피드백과 복구 방안이 제공되는지 검증

### 전제조건
- 회원가입 페이지 접속 상태
- 네트워크 시뮬레이션 가능 환경

### 테스트 단계
1. **네트워크 오류 시뮬레이션**
   - 네트워크 연결 차단
   - 회원가입 시도
   - 에러 메시지 및 재시도 옵션 확인

2. **서버 에러 시뮬레이션**
   - 서버 응답 지연 또는 500 에러
   - 적절한 에러 처리 확인

3. **폼 데이터 보존**
   - 에러 발생 후 입력 데이터 유지 확인
   - 재시도 시 데이터 복원 확인

### 예상 결과
- 네트워크 오류 시 명확한 안내 메시지
- 재시도 버튼 또는 새로고침 가이드 제공
- 사용자 입력 데이터 보존
- 복구 후 정상 진행 가능

### 실패 조건
- 에러 상황 방치
- 불명확한 에러 메시지
- 사용자 데이터 유실
- 복구 방안 부재
