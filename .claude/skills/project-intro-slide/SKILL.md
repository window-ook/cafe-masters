# Project Intro Slide

회사에서 새 프로젝트를 시작할 때 다른 팀원들에게 보여줄 소개 프레젠테이션을 만드는 스킬이다. CEO가 SETTLA 데모 PT의 디자인 퀄리티를 보고 회사 공식 양식으로 채택했기 때문에, 동일한 디자인 시스템과 슬라이드 구조를 따르면서도 프로젝트별 내용을 자유롭게 커스텀할 수 있도록 설계되었다.

결과물은 단일 HTML 파일로, 브라우저에서 바로 열어 프레젠테이션할 수 있다.

## 워크플로우

### Step 1: 레퍼런스 읽기

아래 두 파일을 반드시 먼저 읽는다:
1. [SLIDE-GUIDE.md](SLIDE-GUIDE.md) — 슬라이드 타입별 HTML 구조 패턴
2. [TEMPLATE.html](TEMPLATE.html) — CSS + JS가 완성된 골격 HTML

원본 완성체를 참고하고 싶으면 `.claude/references/settlement/SETTLA_DEMO_INTRO.html`을 읽는다.

### Step 2: 사용자 정보 수집

사용자가 이미 제공한 정보는 건너뛰고, 빠진 항목만 물어본다. 한 번에 몰아서 묻지 말고, 핵심부터 확인한다.

**반드시 필요:**
- 프로젝트명 (영문, 예: SETTLA)
- 상위 브랜드/제품명 (예: TEACHITA)
- 한 줄 설명 (태그라인)
- 발표자, 날짜

**있으면 훨씬 좋은 것:**
- 핵심 KPI (Before → After 수치 2~3개)
- 현재 프로세스 (AS-IS) — 누가 무엇을 어떻게 하는지 단계별
- 문제점 (AS-IS) vs 해결책 (TO-BE) 대비
- 솔루션의 핵심 기능 2~3가지 (KICK 포인트) + 각각의 데모 데이터
- 기술 아키텍처, 로드맵
- 마무리 메시지/슬로건

### Step 3: 슬라이드 구성 결정

정보량에 따라 슬라이드 수를 5~12장 범위에서 결정한다.

**표준 9장 구성** (SETTLA 원본과 동일):

| # | 타입 | 배경 | 설명 |
|---|------|------|------|
| 1 | cover | 라이트 | 프로젝트명 + 태그라인 + KPI 티저 |
| 2 | dark-flow | 다크 | 현재 프로세스 (AS-IS) 흐름도 |
| 3 | comparison | 라이트 | AS-IS vs TO-BE 비교 |
| 4 | dark-flow | 다크 | 솔루션 플로우 (TO-BE) 흐름도 |
| 5 | kick | 라이트 | 핵심 기능 #1 상세 (KPI + 테이블) |
| 6 | kick | 라이트 | 핵심 기능 #2 상세 |
| 7 | kick | 라이트 | 핵심 기능 #3 상세 (선택) |
| 8 | split | 라이트 | 아키텍처 + 로드맵 |
| 9 | closing | 다크 | 마무리 + KPI 요약 + 슬로건 |

사용자가 슬라이드를 추가/삭제/순서변경하고 싶다면 유연하게 대응한다.

### Step 4: HTML 생성

TEMPLATE.html을 기반으로, SLIDE-GUIDE.md의 패턴을 따라 각 슬라이드의 HTML을 작성한다.

**핵심 원칙:**
- 960×540px 고정 크기, viewport에 맞춰 자동 스케일링
- 다크 슬라이드(#0f0f1a)와 라이트 슬라이드를 교차해서 리듬감 부여
- 숫자/금액에는 `mono` 클래스 적용
- pill 뱃지를 적극 사용하여 상태/카테고리 표현
- 테이블은 `.mini-table`로, KPI는 `.kpi-card`로 구성
- 모든 슬라이드에 `<div class="slide-number">N / TOTAL</div>` 포함
- 다크 슬라이드에서는 모든 텍스트 색상을 밝은 톤(#e0e0e0, #bbb 등)으로 조절

**커스텀 자유도:**
- 사용자가 accent color를 바꾸고 싶으면 `:root`의 `--blue` 계열을 다른 색으로 교체 가능
- 다크 슬라이드의 형광색 팔레트(#4ade80, #f472b6, #22d3ee, #facc15)도 요청에 따라 변경
- 슬라이드 타입을 조합하거나 새 타입을 만들 수 있음 (가이드에 없는 레이아웃도 OK)
- 데이터 양에 따라 폰트 크기, 행 수 등을 유연하게 조절

### Step 5: 저장

기본 경로: `.claude/references/{프로젝트명}/PROJECT_INTRO.html`
사용자가 다른 경로를 지정하면 그곳에 저장한다.

**단일 파일 원칙**: CSS/JS 모두 인라인. 외부 의존성은 Pretendard CDN 링크 하나뿐. 파일 하나만 공유하면 누구든 브라우저에서 바로 볼 수 있다.
