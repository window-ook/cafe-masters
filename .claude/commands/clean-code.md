# 코드 시스템 정화 작업

아래 사항을 기준으로 코드를 점검하고 규칙과 맞지 않는 부분을 발견하면 변경해야 합니다.

## 점검 내용

- 공통 컴포넌트 점검
  - 현재 만들어진 컴포넌트를 제외하고, 동일한 jsx 구조를 가진 요소가 추상화 & 모듈화 되어있지 않은 부분이 있는가?
  - Button.tsx, InputField.tsx가 커스텀 자유도가 제한적이지 않은가?

- 컴포넌트 네이밍 컨벤션 점검
  - 핵심 요소에 맞는 일관성있는 컨벤션을 가지고 있는가?

- 디렉토리 세그멘테이션, 네이밍 점검과 개선
  - `/components/shared` 에 위치한 .tsx 파일들이 적절한 하위 트리에 배치되어있는가?

- 불필요한 주석 삭제
  - 함수 내에서 단순히 로직 설명을 하는 인라인 js 주석

- 클라이언트 컴포넌트/서버 컴포넌트 적용 기준 점검
  - 'use client' 지시자가 필요한 곳에만 정확히 선언되어 있는가?
  - 서버 컴포넌트로 작성 가능한데 불필요하게 클라이언트 컴포넌트로 작성된 부분은 없는가?

- 데이터 페칭 로직 성능 점검
  - 캐싱과 에러 핸들링 로직이 올바른지?
  - useQuery/useMutation 훅의 쿼리 키가 `queries/**` 팩토리에서 올바르게 관리되는가?

- 싱글라인 스코프 구현 패턴 준수 점검
  - if문, 화살표 함수의 단일 실행문에서 불필요하게 중괄호 {}를 사용하지 않는가?
  - Early Return 패턴이 일관성있게 적용되었는가?

- TypeScript 타입 안전성 점검
  - interface 선언에 `I-` 접두사가 일관성있게 적용되었는가?
  - interface에 `-Props` 같은 불필요한 접미사가 사용되지 않았는가?
  - 모든 interface가 export 되어있는가?
  - any 타입 사용이 최소화되어 있는가?

- 서버 액션 패턴 준수 점검
  - 서버 액션에서 try-catch를 사용하지 않고 Early Return으로 에러 처리하는가?
  - 모든 서버 액션이 'use server' 지시자를 포함하는가?
  - 반환 타입이 IServerActionResponse 또는 명확한 타입으로 제한되어 있는가?

- 상태 관리 패턴 점검
  - Zustand 스토어를 사용할 때 전체 스토어가 아닌 특정 상태만 선택적으로 구독하는가?
  - URL 상태는 usePathMatcher를 통해 일관성있게 관리되는가?
  - 서버 상태는 React Query로, 클라이언트 상태는 Zustand로 명확히 구분되어 있는가?

- Path 및 Query Key 중앙화 점검
  - 하드코딩된 경로 문자열 대신 `lib/paths.ts`를 사용하는가?
  - 쿼리 키가 `queries/**` 팩토리로 중앙화되어 있는가?

- 메시지 상수 관리 점검
  - Toast 메시지나 콘솔 로그가 `utils/constants/messages.ts`에 정의되어 있는가?
  - 하드코딩된 메시지 문자열이 없는가?

- Tailwind CSS className 순서 점검
  - CLAUDE.md에 정의된 우선순위 규칙(포지션 → 레이아웃 → 외곽 효과 → 배경색 → 공백 → Flex/Grid → 폰트 → 애니메이션 → 트랜지션)을 따르는가?
  - w-와 h-가 동일한 경우 size-로 통일되어 있는가?

- 성능 최적화 패턴 점검
  - useMemo, useCallback이 적절한 곳에만 사용되고 과도하게 사용되지 않는가?
  - 복잡한 필터링, 연산, 이벤트 핸들러에서 메모이제이션이 적용되어 있는가?
  - 무거운 컴포넌트에 대해 동적 import가 고려되었는가?

- 에러 핸들링 패턴 점검
  - ErrorBoundaryWrapper가 적절한 위치에 배치되어 있는가?
  - 에러 메시지가 사용자 친화적인가?
  - Suspense와 loading.tsx가 적절히 활용되고 있는가?

- Form 검증 패턴 점검
  - Zod 스키마가 `schema/` 디렉토리에 정의되어 있는가?
  - React Hook Form과 @hookform/resolvers가 올바르게 통합되어 있는가?

- 코드 중복 제거 점검
  - 유사한 로직이 반복되는 부분이 유틸리티 함수로 추상화되었는가?
  - 같은 패턴의 컴포넌트가 여러 번 작성되지 않았는가?

- import 구문 정리
  - 사용하지 않는 import가 없는가?
  - import 순서가 일관적인가? (React → 외부 라이브러리 → 내부 모듈 → 타입)
  - 상대경로보다 @/ alias를 사용하고 있는가?

- 접근성(a11y) 점검
  - 이미지에 적절한 alt 텍스트가 있는가?
  - 버튼과 링크가 의미론적으로 올바르게 사용되었는가?
  - 키보드 네비게이션이 가능한가?

- 보안 점검
  - 사용자 입력이 적절히 검증되고 있는가?
  - 환경 변수가 클라이언트에 노출되어서는 안 되는 민감한 정보를 포함하지 않는가?
  - RLS(Row Level Security) 정책이 Supabase 테이블에 올바르게 적용되어 있는가?
